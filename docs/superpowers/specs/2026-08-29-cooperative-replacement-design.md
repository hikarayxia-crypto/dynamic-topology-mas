# 节点缺失协作补位与鲁棒控制设计

## 1. 目标与范围

本阶段在现有连续二维协同搜索、动态拓扑和通信总线上实现一个可解释、可复现的
分布式协作补位基线。节点失联后，剩余智能体通过心跳、状态传播和确定性竞价，
接管失效节点原本负责的搜索带；节点稳定恢复后再平滑交还任务。

本阶段必须满足：

- 不读取未知目标坐标；
- 不由环境直接指定补位者；
- 补位信息通过现有 `CommunicationBus` 传播；
- 支持节点故障、通信分区、丢包和重连；
- 不改变原有 `RuleBasedSearchAgent` 行为，新增独立补位策略作为对照；
- 保持现有 `Observation`、`Action` 和动态拓扑公开接口兼容；
- 所有新增核心类、函数、状态机和公式添加中文说明；
- 只报告实际运行结果，不把快速验证解释为正式实验结论。

## 2. 方案选择

采用“基于邻居消息传播的分布式确定性竞价”。

未采用集中式环境分配，因为它会让环境掌握并直接下发全局最优补位者，无法反映
通信分区和消息丢失对协作决策的影响。未在本阶段直接采用学习式任务分配，因为
当前尚无充分训练数据和正式收敛结果；确定性算法更适合作为后续 Graph-MAPPO
补位策略的可解释基线。

## 3. 模块边界

### 3.1 `coordination/replacement.py`

负责纯算法状态，不直接移动智能体：

- `ReplacementConfig`：故障确认、竞价、恢复稳定、广播周期和代价权重；
- `CoverageLane`：固定搜索带标识、原负责人和中心纵坐标；
- `ReplacementBid`：缺失节点、竞价者、分数、创建时间和有效期；
- `ReplacementAssignment`：当前赢家、接管时间和搜索带；
- `ReplacementCoordinator`：单个智能体持有的心跳、缺失检测、竞价合并、赢家
  选择和恢复交还状态机。

该模块只依赖 Python 标准库、NumPy 和项目已有数据结构，不依赖环境内部私有
字段，便于独立单元测试。

### 3.2 `agents/replacement_agent.py`

新增 `ReplacementSearchAgent`，继承现有规则搜索策略或复用其公共扫描逻辑：

- 正常状态搜索自己的固定搜索带；
- 每个决策周期消费通信收件箱并更新协调器；
- 按广播周期发送心跳、已知状态和竞价摘要；
- 自己赢得竞价后，优先驶向缺失节点搜索带；
- 同时承担多个补位任务时按接管时间轮转，避免永久忽略某条搜索带；
- 动作元数据写入补位目标、搜索带中心和竞价分数，供环境记录指标；
- 继续使用原有邻居排斥，保证补位过程中具备基本避碰能力。

### 3.3 环境与评估扩展

`Continuous2DSearchEnv` 不参与竞价，只读取动作元数据，记录当前有哪些缺失任务
正在被接管、补位者是否到达对应搜索带，以及任务切换次数。

`evaluation.metrics` 和 `evaluation.evaluator` 增加补位响应时间、覆盖恢复时间、
平均未覆盖搜索带比例和任务切换次数。普通规则策略没有补位动作时，相关恢复
指标保持 `None`，不得伪造为零。

## 4. 固定搜索带与节点身份

智能体初始完整名单按稳定字符串键排序。第 `i` 个节点在高度为 `H`、总节点数
为 `N` 的区域中拥有固定搜索带：

```text
lane_y(i) = (i + 0.5) * H / N
```

搜索带归属在回合内保持不变。节点失效后不会重新压缩全部在线节点的索引，否则
剩余节点会整体改变搜索轨迹，难以判断谁在补位。缺失节点的固定搜索带成为待接
管任务；恢复节点仍保留原始归属。

## 5. 消息协议

所有协调消息使用普通 `Message.payload` 字典，`kind` 固定为
`"replacement_gossip"`，包含：

```python
{
    "kind": "replacement_gossip",
    "sender": "agent-0",
    "sent_at": 2.4,
    "heartbeats": {"agent-0": 2.4, "agent-1": 2.2},
    "bids": {
        "agent-2": {
            "bidder_id": "agent-0",
            "score": 0.63,
            "created_at": 2.4,
            "expires_at": 4.4,
        }
    },
}
```

节点只接受字段完整、时间有限、智能体标识属于初始名单的协调消息。过期竞价、
未来时间戳、未知节点和非有限分数会被拒绝，不改变本地状态。节点会在后续广播
中携带已知心跳和最佳竞价，实现多跳邻居传播；相同信息通过时间戳去重。

## 6. 状态机

每个节点对初始名单中的其他节点维护以下状态：

1. `HEALTHY`：最近心跳未超时；
2. `SUSPECTED`：心跳超过 `failure_timeout`，但尚未完成确认；
3. `MISSING`：持续缺失达到 `failure_confirmation`，开始竞价；
4. `RECOVERING`：重新收到心跳，但尚未持续稳定；
5. `HEALTHY`：恢复持续达到 `recovery_stability`，撤销补位任务。

竞价从进入 `MISSING` 开始，至少等待 `bid_window` 后才确定赢家。任务一旦分配，
除非赢家失联、竞价过期或新候选分数至少改善 `switch_margin`，否则不切换，避免
轻微位置变化造成抖动。恢复节点稳定前，原补位者继续覆盖对应搜索带。

## 7. 竞价代价

候选节点 `a` 接管缺失节点 `m` 的总分为：

```text
score(a, m) =
    distance_weight * normalized_distance_to_lane
  + load_weight * current_assignment_count
  + connectivity_weight * connectivity_cost
  + energy_weight * energy_cost
```

其中：

```text
normalized_distance_to_lane = abs(agent_y - lane_y) / world_height
connectivity_cost = 1 / (1 + current_neighbor_count)
energy_cost = 1 - clipped_energy
```

默认权重分别为 `0.55、0.20、0.15、0.10`，总和必须为 1。分数越低越优。
收到多个竞价时，按 `(score, bidder_id)` 排序；标识作为最终平局裁决，保证同一
消息集合下所有节点得到一致结果。

候选节点不得为当前缺失节点，也不得为本地已经确认缺失的节点。一个节点可以
接管多个搜索带，但负载项会自然促使任务分散到其他在线节点。

## 8. 补位运动控制

普通搜索仍采用左右往返扫描。补位任务激活后：

1. 将目标纵坐标切换为缺失节点固定搜索带中心；
2. 保持当前横向扫描方向，避免突然反向造成大幅振荡；
3. 纵向误差较大时提高纵向分量，但最终动作仍归一化到单位圆；
4. 叠加现有邻居排斥向量；
5. 到达搜索带容差后开始正常往返覆盖；
6. 多个任务按固定驻留步数轮转；
7. 原节点稳定恢复后，在当前驻留周期结束时交还，不在单步中强制跳转。

该控制器属于可解释鲁棒规则基线，不声称全局最优。

## 9. 指标定义

- `replacement_response_time`：节点进入 `MISSING` 到首次出现有效补位动作的时间；
- `coverage_recovery_time`：节点进入 `MISSING` 到补位者首次进入对应搜索带容差的
  时间；
- `uncovered_lane_ratio`：缺失且尚无有效补位者的搜索带数除以初始搜索带总数；
- `replacement_switches`：同一缺失任务在一个回合内更换补位者的次数；
- `replacement_success_rate`：进入 `MISSING` 的任务中，在回合结束前恢复覆盖的
  比例。

环境从动作元数据和真实位置计算指标，不依赖智能体自报“已经到达”。若故障未
持续到确认阈值，则不计为补位任务；若回合结束前没有补位，则响应和恢复时间为
`None`。

## 10. 错误处理与边界条件

- 仅剩一个在线节点时允许其接管全部缺失搜索带；
- 全部节点失效时沿用环境现有截断逻辑，不生成虚假补位者；
- 通信完全分区时各分区可以形成局部赢家，重连后按竞价顺序合并；
- 竞价过期后必须重新计算，不能永久沿用旧位置产生的分数；
- 节点能量耗尽视为缺失，不自动恢复；预定临时故障可按环境机制恢复；
- 未知或格式错误的消息只被忽略，不终止仿真；
- 配置中的时间、容差和权重必须为有限非负数，权重和必须近似等于 1。

## 11. 测试策略

严格采用红—绿—重构循环，按以下行为拆分测试：

1. 心跳超时依次进入 `SUSPECTED` 和 `MISSING`；
2. 短暂丢包未达到确认时间时不触发补位；
3. 恢复心跳必须持续稳定后才撤销任务；
4. 手工给定候选状态时，最低总代价赢得竞价；
5. 分数相同按智能体标识稳定裁决；
6. 多个缺失任务因负载项分配给不同节点；
7. 邻居传播后，非直连节点能学习心跳和最佳竞价；
8. 过期、未知节点和非有限竞价不会污染状态；
9. 补位智能体朝缺失搜索带移动，且动作保持二维有界；
10. 节点恢复后在驻留周期结束时交还；
11. 环境只记录实际动作中的补位元数据；
12. 评估正确区分响应、覆盖恢复和从未恢复；
13. 在丢包、临时分区和重连条件下运行最小集成回合；
14. 原有全部测试继续通过。

## 12. 非目标

本阶段不实现学习式竞价权重、全局最优任务规划、复杂路径规划、障碍物避障、
拜占庭恶意节点防御或真实无线网络协议。它们不影响本阶段交付一个可测试的节点
缺失协作补位与鲁棒控制基线。
